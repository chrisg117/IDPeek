# IDPeek Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A client-only addon for the Legion 7.3.5 client that previews candidate kit, spell, display, model, texture and WorldEffect ids in a panel, so visual candidates can be compared without touching the server.

**Architecture:** `IDPeek` (always loaded) holds the panel, the parser, the entry list and three preview views. `IDPeek_Data` (load on demand) holds a generated Lua table mapping spells to visuals and kits, and WorldEffects to model files. A Python generator on the host builds that table from the server's extracted db2 files.

**Tech Stack:** WoW 7.3.5 (build 26972) Lua/FrameXML API, `## Interface: 70300`; Python 3 on the host `chris@172.30.1.185` with `/tmp/stage1/wdc1.py` and `rel.py`; Python 3.7 on the PC is `py`.

**Spec:** `E:\Legion\Interface\AddOns\IDPeek\docs\specs\2026-10-21-idpeek-design.md`

## Global Constraints

- Client only: no server code, no server state, no launcher sync.
- Install root: `E:\Legion\Interface\AddOns\`; folders `IDPeek` and `IDPeek_Data`.
- Git repo is `E:\Legion\Interface\AddOns\IDPeek` only; `IDPeek_Data` is generated output, never edited by hand. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nothing is pushed anywhere.
- APIs proven in game: `PlayerModel:ApplySpellVisualKit(kit, oneShot)`, `PlayerModel:SetDisplayInfo(id)`, ModelScene actor `:SetModelByFileID(fdid)`, `Texture:SetTexture(fdid)`. Do NOT use `SetSpellVisualKit` (absent) or `PlayerModel:SetModel(fdid)` (draws a placeholder cube).
- Types in the dropdown, in this order: `kit`, `spell`, `display`, `model`, `texture`, `worldeffect`.
- Label format: `3 / 7 · kit 55752`; expanded entries: `2 / 5 · spell 205128 → visual 12345 → kit 67890`; worldeffect: `1 / 2 · worldeffect 735 → model 200316`; unknown spell/worldeffect: `1 / 1 · spell 999999 not in table`.
- No Lua interpreter on the PC. Lua is verified in game by the user (`/reload`), with Lua errors shown (`/console scriptErrors 1`).
- Host db2 dir: `/home/chris/arguscore-server/data/dbc/enUS/`.

## Review Focus

1. Arrow keys: with the panel open and the edit box unfocused, Left/Right flip entries and every other key still reaches the game (movement, keybinds); with the panel hidden, Left/Right turn the character as normal; while typing in the edit box, Left/Right move the cursor. (Task 2, step 5 checks.)
2. Empty or junk input (`""`, `abc`, `55752,,x`): no Lua error, valid ids kept, one chat line per bad token, empty list shows `0 / 0` and a blank preview. (Task 2.)
3. `IDPeek_Data` missing or disabled: entering a spell list prints one chat line (`IDPeek: IDPeek_Data not loaded (<reason>)`) and gives no Lua error. (Task 4.)
4. Kit after kit: moving to the next kit entry does not leave the previous kit's effect on the stand-in (the stand-in is re-set before each kit). (Task 3.)
5. Changing the dropdown after a list was entered re-parses the edit box text with the new type. (Task 2.)

### Task 2: Panel, parser, entry list and navigation

**Files:**
- Create: `IDPeek/IDPeek.toc` (`## Interface: 70300`, `## Title: IDPeek`, `## SavedVariables: IDPeekDB`; loads `Parse.lua`, `Entries.lua`, `Preview.lua`, `Panel.lua` in that order), `IDPeek/Parse.lua`, `IDPeek/Entries.lua`, `IDPeek/Panel.lua`, `IDPeek/Preview.lua` (stub for this task)

**Interfaces:**
- Shared namespace: `local _, IDPeek = ...` in every file.
- `IDPeek.Parse(text) -> ids (array of numbers), bad (array of strings)`: splits on commas and whitespace; tokens that are not all digits go to `bad`; order and duplicates kept.
- `IDPeek.BuildEntries(kind, ids) -> entries`: entry = `{ view = "model"|"scene"|"texture", kind = "kit"|"display"|"model"|"texture", id = number, chain = string }`. In this task `kit`→view `model`, `display`→`model`, `model`→`scene`, `texture`→`texture`, `chain` = `"<kind> <id>"`. `spell`/`worldeffect` are added in Task 4.
- `IDPeek.Preview` stub: `Show(entry)` and `Clear()` that do nothing yet; real ones in Task 3.
- Panel state: `IDPeek.entries`, `IDPeek.index`; `IDPeek.Go(delta)` moves with wrap and calls `IDPeek.Preview:Show(entry)` and updates the label.

### Task 4: Spell and WorldEffect expansion

**Files:**
- Modify: `IDPeek/Entries.lua`

**Interfaces:**
- Consumes the `IDPeek_Data` global (Task 1) and `BuildEntries` (Task 2).
- `BuildEntries("spell", ids)`: on first use `LoadAddOn("IDPeek_Data")`; one `kit` entry per kit, `chain = "spell <id> → visual <v> → kit <k>"`. `BuildEntries("worldeffect", ids)`: one `scene` entry `{kind="model", id=fdid}`, `chain = "worldeffect <id> → model <fdid>"`. Unknown id: one entry with `view = nil`, `chain = "<kind> <id> not in table"`, and `Preview:Show` treats `view = nil` as `Clear()`.
